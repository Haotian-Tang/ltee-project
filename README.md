# LTEE variant calling

Variant calling on three E. coli samples from the Long-Term Evolution Experiment

Author: Haotian Tang

## Current status

Lesson 05 provides a working Pixi task pipeline for the three LTEE samples.
`pixi run reproduce` verifies the raw data, runs FastQC and MultiQC, aligns
the reads, and calls and filters variants at the course default minimum
read depth of 2. Raw data remain read-only and generated files are excluded
from Git.

The `default` environment supports Linux, macOS and Windows. The `pipeline`
environment adds the bioinformatics tools on Linux and macOS; on Windows,
run the pipeline in WSL2. The manifest and lock file are committed together.
Verified tool versions, local results and the practice-workspace checks are
recorded in `docs/notes.md`.

## Reproduce the results

You need [Pixi](https://pixi.prefix.dev/latest/) and an internet connection.
Then, from this folder:

```bash
pixi install --locked --all   # install both environments from the lock file
pixi run reproduce            # verify data, run QC, align and call variants
```

`pixi run reproduce` must work on a fresh clone of this repository. A GitHub
Action (`.github/workflows/reproduce.yml`) checks that on every push.

## Conda and Mamba users

The pipeline environment is also exported for collaborators without Pixi:

```bash
conda env create -p ./conda-env -f envs/pipeline.yml
conda run -p ./conda-env samtools --version
conda run -p ./conda-env fastqc --version
```

`envs/pipeline.yml` carries version ranges and is solved again when built.
For exact packages, choose the file in `envs/explicit/` matching your Linux or
macOS platform. See `envs/README.md` for the import example, export commands
and platform limitations. The export contains packages, not Pixi task definitions.
`pixi.toml` and `pixi.lock` remain the project's primary environment record.

## Available tasks

| Command | Purpose |
| --- | --- |
| `pixi run check` | Check Python and Quarto |
| `pixi run download` | Download or verify the seven raw files |
| `pixi run qc` | FastQC for six FASTQ files and a MultiQC summary |
| `pixi run variant-calling` | Align reads, call haploid variants and apply the depth filter |
| `pixi run reproduce` | Run QC and variant calling after data verification |

The tasks select their environment automatically. To run a pipeline tool
directly, use `pixi run -e pipeline TOOL`.

## Generated outputs

- `results/qc/multiqc/multiqc_report.html`: combined QC report.
- `results/bam/`: sorted alignments and indexes.
- `results/vcf/`: filtered variants for each sample.
- `results/stats/`: alignment and variant statistics.
- `data/processed/reference/`: decompressed reference and its indexes.

These files are regenerated by the tasks and are not committed. FastQC
reports include WARN/FAIL flags; a successful pipeline run does not mean all
QC modules passed. See the report and `docs/notes.md` for the observed flags.

## What is where

| Folder | What goes in it | Rule |
|--------|-----------------|------|
| `data/raw/` | Data exactly as you received it | Read-only. Never edit; download it with a script. Not committed. |
| `data/processed/` | Data derived from raw data | Regenerated by code. Not committed. |
| `metadata/` | Sample sheet, data sources, checksums, data dictionary | Small text files, committed. |
| `scripts/` | Code you write (Python, shell) | Committed. |
| `config/` | Parameters for the analysis or workflow | Committed. |
| `workflow/` | Snakemake and Nextflow pipelines | Committed. |
| `notebooks/` | Jupyter notebooks for exploration | Committed, outputs cleared or small. |
| `reports/` | Quarto documents that turn results into a report | Source committed, rendered HTML not. |
| `results/` | Figures, tables, logs made by the code | Regenerated. Not committed. |
| `docs/` | Longer documentation | Committed. |
| `envs/` | Conda `environment.yml` exports, for people without Pixi | Generated from `pixi.toml`. |
| `containers/` | Dockerfile and Apptainer recipe | Committed. |

Each folder has its own `README.md` with more detail.

## Data

Raw reads: a subset (175,000 read pairs per sample) of three *E. coli* clones
from the Long-Term Evolution Experiment (population Ara-3, generations 5,000,
15,000 and 50,000), prepared by Data Carpentry:
<https://doi.org/10.6084/m9.figshare.7726454> (file `sub.tar.gz`, CC0).
Reference genome: *E. coli* B str. REL606, GenBank CP000819.1 (NCBI).
Sources, sample sheet, data dictionary and checksums are in `metadata/`.
Download and verification are automated by `scripts/download_data.py`.

## Data availability

The original reads are available from NCBI SRA BioProject PRJNA295606
(runs SRR2589044, SRR2584863 and SRR2584866). The trimmed, subsampled reads
used here are Data Carpentry's `sub.tar.gz` (figshare file 14418248), under
CC0: <https://doi.org/10.6084/m9.figshare.7726454.v3>.
The reference is *E. coli* B str. REL606, GenBank CP000819.1, assembly
GCA_000017985.1, downloaded from NCBI. Exact download URLs and provider MD5
checksums are in `metadata/sources.tsv`; SHA-256 checksums of the retained
raw files are in `metadata/checksums.sha256`. Sample information is credited
to Data Carpentry (CC BY 4.0), as documented in `metadata/README.md`.

Raw files are downloaded locally, kept read-only and excluded from Git.
Code is available at <https://github.com/Haotian-Tang/ltee-project> under MIT.
To recreate the raw-data collection, run
`pixi run download`. QC reports, alignments, variant calls and statistics are
regenerated with `pixi run reproduce` using the committed manifest and lock file.
